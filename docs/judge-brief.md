# Nivaran AI: reviewer brief

**One problem:** an online refund is already owed but has not arrived. Evidence is scattered
across invoices, refund messages and chats; the consumer needs a checkable next action.
Demand and time saved are hypotheses, not measured population statistics.

**Distinctive design:** the model reads and chooses tools; code checks quotes, detects conflicts,
chooses the escalation step, calculates dates and inserts complaint values. The user settles
uncertainty, approves the plan and sends the complaint. There is no sending/filing/payment tool.

## A dependable three-minute review

1. Open the recorded conflicting-amounts case from Home. Compare both source quotes and the
   recorded answer. This is historical evidence on fictional files; replay is read-only.
2. Review its plan and complaint, then open the already-complained record. Its helpline draft
   failure stays disclosed. Do not infer that every live journey works from a Saved run.
3. Open the labelled invented guided tour. Answer, approve, explicitly prepare the practice
   complaint, type FAKE123456 and remove its flag. This exercises the real renderer/editor/linter
   in page memory without provider quota. It is not an agent run or a new model success.

The third step requires the 6 October improvement build to be deployed. The public version can
lag the repository; check release evidence before describing a new feature as public.
